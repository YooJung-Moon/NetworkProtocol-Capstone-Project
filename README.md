# FSM 기반 마피아 게임 통신 프로토콜

## 프로젝트 개요

본 프로젝트는 **FSM(Finite State Machine)** 구조를 기반으로 마피아 게임의 역할 분배, 낮/밤 진행, 투표, 직업별 행동, 게임 종료 과정을 C++로 구현한 통신 프로토콜 프로젝트입니다.

플레이어는 `Host`와 `Guest`로 구분됩니다. `Host`는 전체 게임 진행과 메시지 송수신을 관리하며, `Guest`는 게임 시작 시 랜덤으로 `Mafia`, `Doctor`, `Police`, `Citizen` 중 하나의 역할을 부여받습니다.

## 주요 기능

- Host / Guest 기반 게임 진행
- 랜덤 역할 분배
- 낮 상태에서 생존자 단체 채팅
- 생존자 투표 및 처형 처리
- 마피아의 공격 대상 선택
- 의사의 보호 대상 선택
- 경찰의 역할 확인 기능
- 게임 종료 조건 판별
- ACK 기반 메시지 수신 확인

## 구현 방식

### 역할 분배

게임 시작 후 Host는 Guest들에게 역할을 랜덤으로 배정합니다.

각 Guest는 자신의 역할을 수신한 뒤 ACK를 전송하며, Host는 ACK를 확인한 후 다음 플레이어에게 역할 정보를 전송합니다. 이를 통해 역할 분배 과정에서 메시지가 안정적으로 전달되도록 구성했습니다.

### 낮 진행

낮에는 살아있는 Guest들이 단체 채팅을 진행합니다.  
Host는 게임 진행을 관리하지만, 낮 채팅 메시지 내용은 직접 수신하지 않도록 구현했습니다.

### 투표 처리

Host는 생존자 목록을 각 Guest에게 전달하고, Guest는 전달받은 목록을 기준으로 투표할 대상을 선택합니다.

투표 시 다음 조건을 검사합니다.

- 자기 자신에게 투표할 수 없음
- 생존자 목록에 포함된 ID만 선택 가능
- 유효하지 않은 입력은 다시 입력 요청

Host는 모든 투표 결과를 수신한 뒤 득표 수를 집계합니다. 최다 득표자가 한 명이면 해당 플레이어를 처형하고, 동점이면 처형 없이 다음 단계로 진행합니다.

### 밤 진행

밤에는 역할별 행동이 순차적으로 진행됩니다.

- `Mafia`는 제거할 대상을 선택합니다.
- `Doctor`는 보호할 대상을 선택합니다.
- `Police`는 정체를 확인할 대상을 선택합니다.
- `Citizen`은 별도의 밤 행동 없이 대기합니다.

Host는 각 역할의 입력 결과를 저장하고, 공격 대상과 보호 대상을 비교하여 피해 여부를 결정합니다.

### 게임 종료 처리

게임 종료 조건이 충족되면 Host는 생존자에게 종료 메시지를 순차적으로 전송합니다. Guest는 종료 메시지를 수신한 뒤 ACK를 전송하며, Host가 모든 ACK를 확인하면 초기 상태로 돌아갑니다.

## 초기 설계 대비 구현 변경 사항

초기 FSM 설계는 다양한 상태와 이벤트를 포함하고 있었지만, 실제 구현에서는 안정적인 실행과 단순한 흐름을 위해 일부 구조를 정리했습니다.

### `TYPING` 상태 생략

초기 설계에서는 밤에 특정 역할이 Host와 소통할 때 `TYPING` 상태를 거치도록 구성했습니다.

실제 구현에서는 별도의 `TYPING` 상태를 사용하지 않고, 각 역할 처리 과정에서 Host와 Guest가 직접 송수신하도록 단순화했습니다.

### `MODE_2` 상태 제거

초기 설계에서는 경찰 행동 이후 `MODE_2` 상태를 거쳐 다음 상태로 전환되도록 구성했습니다.

실제 구현에서는 중간 상태를 제거하고, 경찰 행동이 끝난 뒤 바로 다음 단계로 넘어가도록 변경했습니다.

### 수신 이벤트 단순화

초기 설계에는 여러 세부 수신 이벤트가 존재했지만, 구현 과정에서 중복되거나 유사한 이벤트를 통합했습니다.

이를 통해 FSM 흐름을 단순하게 유지하고, 상태 전이 로직을 더 직관적으로 관리할 수 있도록 했습니다.

## 주요 변수

| 변수 | 설명 |
|---|---|
| `change_state` | FSM 진행 상태를 제어하는 외부 트리거 |
| `waitingAck` | ACK 수신 대기 여부 |
| `waitingHostInput` | Host 입력 대기 여부 |
| `currentSendIndex` | 현재 메시지를 전송할 플레이어 인덱스 |
| `voteResults[]` | 투표 결과 저장 배열 |
| `sentVoteId` | 마피아가 선택한 공격 대상 |
| `doctorTarget` | 의사가 선택한 보호 대상 |
| `idead` | 플레이어 사망 여부 |

## 프로젝트 특징

- FSM 기반으로 게임 진행 흐름을 체계적으로 관리
- Host 중심의 메시지 송수신 구조 구현
- ACK를 활용한 통신 확인 처리
- 유효성 검사를 통한 투표 오류 방지
- 초기 설계를 실제 구현에 맞게 단순화
- 역할 추가 및 기능 확장이 가능한 구조
